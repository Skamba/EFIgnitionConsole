EFIgnition Console - wiring and setup
=====================================

This display listens to an EFIgnition 46 engine management unit over CAN and shows
the live values on a 20x4 character LCD. A helper Arduino Mega 2560 does the work;
the ECU itself is not modified in any way.

Earlier versions of this project talked to a Speeduino over its secondary serial
port. That is gone. The EFIgnition 46 is a MegaSquirt-2/Extra based unit and does
not speak the Speeduino protocol. See "Why CAN" at the bottom.


What you need
-------------

- Arduino Mega 2560 (helper board)
- 20x4 character LCD with an I2C backpack
- MCP2515 CAN module with a TJA1050 transceiver
- Fuel pressure sensor (the one that used to hang on the Speeduino)
- 120 ohm resistor, only if the CAN module does not already have one

The MCP2515 module is the only new part compared to the Speeduino setup.

Watch the crystal on the CAN module. They ship with either an 8 MHz or a 16 MHz
crystal, printed on the metal can or on the silkscreen. It must match CAN_CRYSTAL
in src/main.cpp. Get this wrong and the module still starts up quite happily, it
just listens at the wrong bit rate and nothing ever arrives.


Wiring
------

1. LCD to the Mega (I2C)

   LCD backpack SDA   ->  Mega pin 20
   LCD backpack SCL   ->  Mega pin 21
   LCD backpack VCC   ->  Mega 5V
   LCD backpack GND   ->  Mega GND

   The backpack address is 0x27 in src/main.cpp. Some boards ship as 0x3F; if the
   screen stays blank but the backlight works, that is the first thing to try.

2. CAN module to the Mega (SPI)

   MCP2515 CS    ->  Mega pin 53      also printed as NSS or SS
   MCP2515 SI    ->  Mega pin 51      also printed as MOSI or SDI
   MCP2515 SO    ->  Mega pin 50      also printed as MISO or SDO
   MCP2515 SCK   ->  Mega pin 52      also printed as CLK
   MCP2515 VCC   ->  Mega 5V
   MCP2515 GND   ->  Mega GND
   MCP2515 INT   ->  not connected

   The silkscreen wording varies between makers, hence the notes on the right.
   SI and SO are the pair that gets crossed: SI is the module's input, so it comes
   from the Mega's output on pin 51. Swap those two and the module never answers,
   which the display reports as "CAN chip not found".

   Pins 50 to 52 are the Mega's hardware SPI and cannot be moved. Only the chip
   select is free; it is CAN_CS_PIN in src/main.cpp. The interrupt line is left
   off on purpose: the firmware empties the receive buffer in its main loop, which
   is fast enough for four messages at 20 Hz.

3. CAN module to the ECU

   MCP2515 CAN-H  ->  ECU CAN-H
   MCP2515 CAN-L  ->  ECU CAN-L

   Ask EFIgnition which pins on the connector carry CAN. Do not guess.

   Use a twisted pair for these two. A CAN bus wants exactly two 120 ohm
   terminating resistors, one at each end. Most MCP2515 modules have one fitted,
   sometimes behind a jumper. Check whether the ECU has one too: two is correct,
   three makes the signal too weak, one makes it reflect.

4. Fuel pressure sensor to the Mega

   Sensor signal  ->  Mega A0
   Sensor 5V      ->  Mega 5V
   Sensor ground  ->  Mega GND

   This sensor used to be wired to the Speeduino, which had a spare analogue
   input. The EFIgnition 46 has three analogue inputs and all three are taken by
   the wideband, the MAP sensor and the throttle position sensor, so there is no
   room for it there.

   Nothing is lost by moving it here. The Speeduino only ever displayed the value:
   there is no fuel pressure correction or protection in its firmware, unlike oil
   pressure, which does have one. The reading was for the driver, not for the ECU.

   A 0 to 5 V sensor connects straight to an analogue input; no divider needed.
   Confirm the sensor does not swing above 5 V before connecting it.

   Then set the calibration in src/main.cpp. FUEL_PRESSURE_CBAR_AT_0V and
   FUEL_PRESSURE_CBAR_AT_5V are the pressure in hundredths of a bar at 0 V and at
   5 V, the same two-point form TunerStudio uses. The defaults suit a 0.5-4.5 V
   sensor rated 0 to 60 psi. Read the type off the sensor and recalculate; do not
   copy the old Speeduino numbers, which described a straight 0 to 5 V line and
   were probably wrong for that sensor.

5. Old wiring to remove

   The serial link on Mega pins 18 and 19 went to the Speeduino and has no purpose
   any more. So do the 10k resistors that sat in those two wires.


Setting up the ECU
------------------

One switch. In TunerStudio, open CAN bus / Testmodes > Dash Broadcasting and set
Enable to on. Leave Configuration on "Automatic".

Automatic means base identifier 1512 and 20 Hz, which is what src/main.cpp expects.
If you switch to Advanced and change the base identifier, change CAN_BASE_ID to
match.

Nothing else in the tune needs to change. The other CAN broadcasting options are
for linking several MegaSquirt units together and can stay off.


What is on the screen
---------------------

    4200rpm   210C   31C
     105kPa    85%   28°
    12.8afr (12.5) 14.1V
     3.0bar  3.40ms  77%

    row 1  engine speed, cylinder head, inlet air
    row 2  manifold pressure, throttle, ignition advance
    row 3  measured AFR, target AFR in brackets, board voltage
    row 4  fuel pressure, injector pulse width, injector duty

Every field has room for three digits, because a cylinder head on this engine
runs around 150 C and peaks past 200. A tighter layout would run the two
temperatures together exactly when the engine is hot enough that you want to
read them.

Dashes in a field mean the CAN message carrying that value has stopped arriving.
Values are blanked per message rather than left frozen, so a stale reading can
never be mistaken for a live one.

The character in the bottom right corner is blank while all four CAN messages keep
arriving. A digit there is the number of messages that have gone quiet. An E means
the CAN controller itself reports a bus fault - error passive or bus off.


When nothing arrives
--------------------

The display works out which kind of nothing it is looking at, and says so. Each
screen points at something different to check.

  "CAN chip not found"
      The MCP2515 never answered over SPI, so the problem sits between the Mega
      and the module. Check the SPI wiring, chip select on pin 53, and power.

  "No CAN data received" / "Bus is quiet"
      The controller works, but there is nothing at all on the wire - not even
      something it fails to decode. Check that Dash Broadcasting is switched on
      in the tune, and that CAN-H and CAN-L are actually connected.

  "No CAN data received" / "Signal but no decode"
      Electrical activity is arriving that will not turn into valid frames; the
      receive error counter is climbing. In order of likelihood: the crystal
      setting (8 versus 16 MHz), CAN-H and CAN-L swapped, and termination. A
      healthy bus measures about 60 ohm across the pair with the power off, which
      is two 120 ohm resistors in parallel. 120 ohm means only one is fitted.

  "CAN bus is alive" / "Saw id 1234 not ours"
      Frames are arriving and decoding cleanly, which proves the wiring, the bit
      rate and the crystal are all right. Nobody is sending our identifiers. The
      screen shows the identifier it did see, so you can compare it with the
      1512 to 1515 this firmware expects and correct the Base CAN identifier.

That last screen is the most useful of the four: it turns "it does not work" into
a number you can read off the display and type into TunerStudio.

Two values from the Speeduino version are not part of the CAN dash broadcast and
have gone: the idle valve position and the engine status letters (R, C, A, W).
Their places went to injector pulse width, target AFR and injector duty, which are
more useful while the tune is still being built.

Injector duty is calculated here, not sent by the ECU. It assumes one injector
opening per engine cycle, which is what sequential injection gives. If the tune is
changed to semi-sequential or batch, update SQUIRTS_PER_CYCLE and ALTERNATE_DIVIDER
in src/main.cpp.


Why CAN
-------

The Speeduino was polled: the display asked, the ECU answered. The EFIgnition 46
can broadcast instead, sending a fixed set of values on its own several times a
second. That removes all the request timing and packet validation the old firmware
needed, and it does not compete with TunerStudio for a connection, so you can tune
on the laptop and watch the display at the same time.

Full detail on the messages, their contents and where those numbers come from is in
the Efignition project repository, docs/12-console.md.
